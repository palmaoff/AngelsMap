# map_core — внешняя карта для «Ангел: Чистые дороги»

Веб-клиент (Leaflet, чистый JS, без сборки) для базы 1С **«Ангел: Чистые дороги»** (конфигурация `СодержаниеДорог`).
Показывает слои карты, дашборд и отчёты в браузере, без тонкого клиента 1С.

Карта состоит из двух половин:

| Половина | Где лежит | Что делает |
|---|---|---|
| **Клиент** (этот репозиторий, ветка `clean-roads`) | `map_core/` | Рисует карту, ходит в 1С по HTTP |
| **Сервер** — расширение 1С `map_api` | проект `clean roads`, каталог `map-api/` | HTTP-сервис `MapAPI`: отдаёт слои, иконки, дашборд, отчёты |

Ядро клиента ничего не знает о смысле слоёв: сервер присылает мета-описание (`GET /layers`), клиент его рисует.
Всё, что специфично для базы, вынесено в плагин `js/backends/clean-roads.js`.

> Ветка `clean-roads` — вариант ядра под эту базу. Плагины других баз (ДТП, мониторинг транспорта) живут в своих ветках.

---

## Быстрый старт

1. **Загрузите расширение `map_api` в базу 1С** (раздел 1).
2. **Опубликуйте базу на веб-сервере вместе с HTTP-сервисами расширения** (раздел 2).
3. **Разместите файлы этого репозитория на том же веб-сервере** (раздел 3).
4. **Пропишите имя публикации в `js/backends/clean-roads.js`** (раздел 4).
5. Откройте страницу в браузере и войдите логином/паролем пользователя 1С (раздел 5).

## 1. Расширение 1С `map_api`

Исходники: проект `clean roads`, каталог `map-api/` (выгрузка расширения в файлы).

| Параметр | Значение |
|---|---|
| Имя расширения | `map_api` |
| Назначение | Customization (исправление) |
| Префикс имён | `mapapi_` |
| Режим совместимости | 8.3.18 |
| HTTP-сервис | `MapAPI`, корневой URL **`map-api`** |
| Общий модуль | `ААКартографияВнешнееAPI` (вся логика) |
| Роль по умолчанию | `mapapi_ОсновнаяРоль` (пустая, прав не выдаёт) |

**Загрузка** (любым из способов):
- Конфигуратор: *Конфигурация → Расширения конфигурации → Добавить*, затем «Загрузить из файлов» на каталог `map-api/`;
- командная строка: `1cv8 DESIGNER /LoadConfigFromFiles <путь>\map-api -Extension map_api`, затем обновление конфигурации БД.

Требования и особенности:
- Основная конфигурация не меняется — всё новое живёт только в расширении.
- Расширение должно быть **активным**; если после загрузки HTTP-сервис отвечает 404 — проверьте это и обновление конфигурации БД.
- Расширение — это **копия** логики форм, а не вызов. Запросы слоёв, дашборд, иконки перенесены копированием из
  `Обработка.КартографияФильтры.Форма.Картография` и `Отчет.РабочийСтол`. **Правка в основной конфигурации
  сама в расширение не попадёт — её нужно повторить вручную в `ААКартографияВнешнееAPI`.**
  То же касается списка картинок `ИконкиДляКарты` → `ПолучитьИконки`.
- Привилегированный режим не используется (кроме чтения настроек карты) — разграничение доступа работает штатно:
  подрядчик видит только свои ТС, треки, дороги, контракты.

### Права пользователей

- Вход — **обычные пользователи информационной базы** (Basic-аутентификация), отдельного технического пользователя нет.
- Внутри сервис работает от имени вошедшего: его фильтры слоёв, его подрядчик (`ПараметрыСеанса.ТекущийПодрядчик`).
- Вкладка «Отчёты» доступна только пользователям с ролью **`ТолькоПросмотр`** (в ней права на отчёты; в роли `Подрядчик` их нет).
  Без прав вместо отчёта будет карточка с ошибкой — лечится ролью в Конфигураторе, не кодом расширения.
- Каждый вошедший пользователь занимает сеанс 1С (учтите лицензии). Сервис использует повторное использование сеансов.

### Какие слои увидит пользователь

Слой показывается, только если в 1С включена функциональная опция `Используются<Слой>`
(проверяются 11 из 13 слоёв, кроме `Треки` и `Заявки`). Выключенный слой сервер просто не присылает.
Если жалуются «в 1С слой есть, а на внешней карте нет» — смотрите опции в 1С, а не клиент.
(Нативная карта проверяет только 4 опции — знаки, остановки, переходы, светофоры — поэтому расхождение штатное.)

Все слои: `ТранспортныеСредства`, `Треки`, `ЗоныВыполненияРабот`, `АвтомобильныеДороги`, `Заявки`,
`АдминистративныеЕдиницы`, `Маршруты`, `МестаРазмещения`, `Мосты`, `Остановки`, `ПешеходныеПереходы`,
`Светофоры`, `ДорожныеЗнаки`.

## 2. Публикация базы на веб-сервере

Клиенту нужен доступ к адресу вида `https://<сервер>/<ИмяПубликации>/hs/map-api/`.

1. Опубликуйте базу (Конфигуратор: *Администрирование → Публикация на веб-сервере*, либо `webinst`) для Apache или IIS.
   Для Linux-сервера 1С — `webinst` + Apache (или nginx как обратный прокси к нему).
2. Включите публикацию **HTTP-сервисов расширений** — иначе `MapAPI` не будет виден.
   В файле публикации `default.vrd` это `<httpServices publishExtensionsByDefault="true" .../>`;
   в `webinst` — ключ `-publishExtensions`. После смены перезапустите веб-сервер.
3. Аутентификация публикации — **не анонимная и не по ОС**: сервис проверяет Basic-заголовок
   против пользователей ИБ. Анонимный доступ включать нельзя.
4. Запомните **имя публикации** (например, `CleanRoads`) — оно понадобится в разделе 4.

Проверка, что сервер поднят (подставьте свои значения):

```
curl -u ЛОГИН:ПАРОЛЬ https://<сервер>/<ИмяПубликации>/hs/map-api/config
```

Ожидаемый ответ — JSON вида `{"center":[широта, долгота],"zoom":N}`.
`401` — неверный логин/пароль или анонимный режим публикации; `404` — не опубликованы HTTP-сервисы расширений
или расширение не активно.

### Эндпоинты сервиса `MapAPI`

Каждый шаблон URL имеет и метод `OPTIONS` (CORS-preflight, который браузер шлёт из-за заголовка `Authorization`).

| Метод и путь | Назначение |
|---|---|
| `GET /config` | Центр и зум карты (учитывает административный центр пользователя) |
| `GET /icons` | Картинки объектов (`img` → data-URI) из библиотеки картинок 1С и видов знаков |
| `GET /layers` | Список слоёв с мета-описанием |
| `GET /layer/{id}` | Данные слоя |
| `GET`/`POST /layer/{id}/settings` | Форма фильтров слоя (есть у 8 слоёв из 13) |
| `GET /object/{layerId}/{objectId}` | Карточка объекта (HTML-фрагмент) |
| `GET /reports`, `GET /report/{id}`, `GET`/`POST /report/{id}/settings` | Два отчёта: «Оценка работы транспортного средства», «Контроль приоритетности выполнения работ» |
| `GET /dashboard`, `GET`/`POST /dashboard/settings`, `POST /dashboard/focus` | Дашборд (порт рабочего стола 1С) |

Слои с формой настроек: `ТранспортныеСредства`, `Треки`, `ЗоныВыполненияРабот`, `АвтомобильныеДороги`, `Заявки`,
`АдминистративныеЕдиницы`, `Маршруты`, `МестаРазмещения`. У остальных пяти в нативной карте фильтров нет.

## 3. Размещение клиента

Клиент — набор статических файлов, ничего собирать не нужно (все библиотеки лежат в `lib/`, работает без интернета).
Точка входа — `index.html`. Файлы нужно отдавать по HTTP(S) — открытие через `file://` не подойдёт.

**Вариант А (рекомендуется): тот же сайт, что и публикация 1С.**
Положите содержимое репозитория в каталог веб-сервера рядом с публикацией, чтобы страница и API имели один origin
(например, `https://<сервер>/map/` и `https://<сервер>/CleanRoads/hs/map-api/`).
Тогда путь `baseUrl` — относительный, CORS не нужен.

**Вариант Б: клиент на другом сервере/домене.**
Укажите в `baseUrl` абсолютный адрес публикации. В сервисе уже заведены CORS-заголовки
(`Access-Control-Allow-Origin: *`, методы `GET, POST, OPTIONS`, заголовки `Content-Type, Authorization`),
так что дополнительных настроек в 1С не требуется. Если публикация стоит за прокси — он не должен вырезать
эти заголовки и обязан пропускать `OPTIONS` без аутентификации.

Для локальной проверки подойдёт любой статический сервер, например `python -m http.server 8080` в корне репозитория
(тогда нужен вариант Б с абсолютным `baseUrl`).

## 4. Настройка клиента под вашу базу

Настройки бэкенда — в начале возвращаемого объекта плагина `js/backends/clean-roads.js`:

```js
baseUrl: '/CleanRoads/hs/map-api/',   // ← имя вашей публикации
fallbackCenter: [56.877, 60.626],     // запасной центр, если /config не ответил
fallbackZoom: 13,
```

- **`baseUrl`** — обязательно замените `CleanRoads` на реальное имя публикации из раздела 2.
  Хвост `/hs/map-api/` неизменен (`hs` — HTTP-сервисы 1С, `map-api` — корневой URL сервиса).
  Для варианта Б — полный адрес: `https://server.example/CleanRoads/hs/map-api/`.
- **`fallbackCenter` / `fallbackZoom`** — только страховка. Реальные значения приходят из `GET /config`.
- Остальное (`serverIcons`, `backgroundLayers`, `playbackMarkerLayer`, дашборд-шаблон и т. д.) менять при развёртывании не нужно.

Подключение плагина — в `index.html`, ровно один тег `js/backends/<id>.js` должен быть раскомментирован
(для этой ветки — `clean-roads.js`, он идёт после `settings-form.js` и до `map.js`).
Переключение бэкенда — только вручную, автоопределения нет. Тег `_demo.js` — синтетический плагин для проверки
точки расширения, в работе не нужен.

**Кеш браузера.** Скрипты подключены с параметром версии (`js/map.js?v=69`). После правки файла увеличьте
номер у его тега в `index.html`, иначе пользователи получат старую версию.

## 5. Первый запуск и проверка

1. Откройте страницу клиента. Появится экран «Вход под учётной записью 1С».
2. Введите логин и пароль пользователя ИБ. Клиент проверяет их запросом `GET /layers`; при успехе заголовок
   Basic сохраняется в `localStorage` браузера (ключ `mapAuth`) до нажатия «Выйти».
3. Должны появиться панель слоёв, карта, переключатель «Карта / Дашборд / Отчёты».

Что означают ошибки на экране входа:

| Сообщение | Причина |
|---|---|
| «Неверный логин или пароль» | сервер ответил 401 |
| «Не удалось подключиться к серверу» | сеть, неверный `baseUrl`, 404, CORS (см. консоль браузера, вкладка Network) |

Типичные проблемы:

| Симптом | Что проверить |
|---|---|
| 404 на `/hs/map-api/...` | опубликованы ли HTTP-сервисы расширений; активно ли расширение; верное ли имя публикации в `baseUrl` |
| Всех выбрасывает на вход | 401 на любом запросе сбрасывает сессию; смена пароля, аутентификация публикации |
| Ошибка CORS | клиент на другом origin: прокси режет заголовки или не пропускает `OPTIONS` |
| Нет слоя, который есть в 1С | функциональная опция `Используются<Слой>` (см. раздел 1) |
| Пустой центр карты | не ответил `/config` — клиент откатился на `fallbackCenter` |
| Вкладка «Отчёты» с ошибкой | у пользователя нет роли `ТолькоПросмотр` |
| Иконки не как в 1С | не пришёл `/icons`; иконка не добавлена в `ПолучитьИконки` (нужна ручная правка в расширении) |
| Долго грузится / тормозит | флаги рендера в `js/config.js`; проверка через URL-параметры (ниже) |

**Тюнинг рендера без правки файла** — параметры адресной строки: `?vtl=0` (выключить векторные тайлы линий),
`?vtp=1` (включить для полигонов), `?pc=0` (SVG вместо canvas), `?pad=0.5`, `?uwi=1`, `?uwz=1`, `?fa=1`.
Значения по умолчанию — в `js/config.js` (`MapConfig.perf`), они уже подобраны замерами.

## Как устроен клиент

```
index.html          точка входа, порядок подключения скриптов важен
css/styles.css      стили
lib/                Leaflet, markercluster, VectorGrid, heat, xlsx — всё локально
js/config.js        MapConfig.perf — тюнинг рендера
js/api.js           весь обмен с 1С (Basic-авторизация, fetch)
js/auth.js          экран входа, выход
js/backends/        плагины баз: clean-roads.js (боевой), _demo*.js (заглушки)
js/map.js           карта, слои, кластеры, треки, воспроизведение
js/settings-form.js модалка с формами фильтров, присланными сервером
js/dashboard.js     экран «Дашборд»
js/reports.js, rich-report.js, export.js   отчёты и выгрузка в XLSX/PDF
js/chart-kit.js     общие примитивы графиков
js/app-shell.js     переключатель Карта / Дашборд / Отчёты
js/icons/           запасные иконки (начало/конец трека, автобус, остановка)
```

Ключевые решения:
- **Сервер присылает только цвета и картинки.** Размеры, толщины линий, заливка и порядок наложения — решение клиента.
- **Подложка:** слой `АдминистративныеЕдиницы` всегда опускается под остальные (`backgroundLayers`),
  как в нативной карте, — иначе район перехватывает клик у вложенных объектов.
- **Иконки точек** берутся с сервера (`/icons`); векторные пиктограммы из `pointIconShapes` — запасные.
- **Треки:** воспроизведение включается по слою с id `Треки`; маркер — картинка ТС, на треке иконки начала/конца.
- **Дашборд** — порт рабочего стола 1С: KPI, транспорт на линии по подрядчикам и адм. единицам, активные контракты.
  Клик по строке подрядчика/единицы переключает на карту с отбором (`POST /dashboard/focus`, меняется только один ключ фильтра).
- **Автообновления слоя ТС нет:** поле `refresh` сервер шлёт, клиент его не читает.
- **Флаг `cluster`** сервер не шлёт — точечные слои всегда идут через кластеризацию.
- Общий фильтр слоёв хранится в тех же ключах `ХранилищеОбщихНастроек`, что и в нативной форме карты, —
  сохранение фильтров во внешней карте затирает поля, которых на её форме нет.

## Справочник контракта слоёв

Ядро понимает следующие необязательные поля мета-описания слоя (`GET /layers`).

### Линейный слой (`type: "line"`)

- `overlays: [{ field, color, selectedColor }]` — подсветки участков: поверх основной линии рисуются
  некликабельные полилинии по полю объекта `field` (массив точек). `selectedColor` — цвет у выделенного объекта.
  Порядок в массиве = порядок наложения.
- `geometryField: "zoneDots"` — брать геометрию линии из этого поля вместо `dots`. Объект с пустой геометрией
  не рисуется. Воспроизведение трека играет то, что нарисовано.
- `trackMarkers: { field, startImg, endImg }` — иконки начала/конца линии: в поле объекта `field` массив
  `{ coords: [lat, lng], time, isStart, isEnd }`, маркеры ставятся только на точки с `isStart`/`isEnd`.
  `startImg`/`endImg` — ключи `GET /icons`; если картинки нет — запасные `js/icons/НачалоТрека.svg` / `КонецТрека.svg`.
  Размер (20px) — решение клиента. Клик выделяет объект.
- `highlightNoRoute: true` — устаревший алиас (мониторинг транспорта): то же, что оверлей
  `{ field: "noRouteDots", color: "red", selectedColor: "#AA226F" }`.
- `legend: [{ label, color }]` — легенда слоя (любой тип), видна, пока слой включён; после сохранения настроек
  слоя `meta` перечитывается и легенда обновляется.

### Формы настроек

Сервер отдаёт HTML формы; клиент понимает атрибуты строк:

- `data-show-if="поле=значение"` — показывать строку только при таком значении поля.
- `data-exclusive-with="поле1,поле2"` — у чекбокса: при включении снимаются отметки с перечисленных чекбоксов.

## Поддержка этого README

Файл описывает и клиент, и его связь с расширением 1С. При изменениях обновляйте его в том же коммите:

- новый/удалённый слой, эндпоинт или поле контракта → разделы 1, «Эндпоинты», «Справочник контракта»;
- смена параметров расширения, публикации, `baseUrl` → разделы 1–4;
- новый флаг `MapConfig.perf` или URL-параметр → раздел 5;
- смена структуры файлов → «Как устроен клиент».
